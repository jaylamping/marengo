## Verified during synthesis

- **L-berthier-25 (card disagreement).** intent/marengo-pi.md §10 L5 and safety-invariants.md App D L-04 say a CommWatchdog error keeps `ControlMode::Position`, so a later enable may resume a stale hold. intent/berthier.md §10 L7 says that preserve branch is dead. The code supports berthier: `ControlLoop::tick` calls `discard_motion_intent()` for every `LoopError::Safety` (`crates/berthier/src/loop.rs:1048-1057`), which sets `ControlMode::Disabled` (`:1459-1463`) before marengo-pi's branch (`bins/marengo-pi/src/main.rs:1432-1444`) runs. The live defect is the swallowed `disable_all()` result.
- **L-armee-kinematics-01.** `JointLimitBounds::new` calls `soft.clamp(hard_lower, hard_upper)` (`crates/armee-kinematics/src/limits.rs:24-25`), and Davout calls `joint_limit_bounds` before its own `hard_lower >= hard_upper` check (`crates/davout/src/lib.rs:2997-3003`). Confirmed as stated.
- **L-motor-repl-01 / L-robstride-02.** On `main`, `pi_motor_enable` and `pi_jog` still audit exit 0 (`tools/marengo-pi-mcp/src/tools/motion.ts:625,788`), and `pi_motor_disable` still says "primary fault clear" (`:632`).
- **L-marengo-pi-01.** On `main`, only `enable-soak.ts` uses `env -u MARENGO_CHAPPE_SOCKET`.
