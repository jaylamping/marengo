## NEEDS-DECISION

### K4 — `approach_velocity_cap` measures the hard wall, the clamp uses the soft wall
- **A (recommended after a bench look): measure to the effective bound.** Replace the hard-wall distance with `q − lo_eff` / `hi_eff − q` from `effective_command_bounds`, still tapering over `margin`. Fixes the mismatch, but the taper then reaches 0 at the soft wall, so a hold-at to the soft bottom approaches exponentially and may creep near the 0.02 rad/s deadband where the cap switches off; that needs one weighted-pitch bench run (supported arm) before it ships.
- **B: keep as is**, document that the cap tapers toward `hard ± margin`. Cost: planner velocity can still be ~0.5·`v_max` at the soft wall for margins under the hard–soft gap (live gap ≤ ~50 mrad), absorbed by the per-tick envelope clamp.
- Needs hardware: trajectory timing near soft walls cannot be validated in simulation.

### K2 follow-up — Berthier's duplicate gate
`envelope_dq_cmd_for_hold_clamp` (`crates/berthier/src/position_setpoint.rs:113-135`) still exempts every target ≤ +5 mrad from cruise-speed `dq_cmd`. Aligning it with the narrowed kinematics gate would send e.g. pitch hold-at −0.85 through the cruise-speed kinetic margin (floor −0.78), so one leg would stop short of the soft bottom (the ADR 0009 "fast moves may not reach the soft limit in one leg" trade-off), where it reaches it today. Option A: leave (current bench behaviour; kinematics already narrower). Option B: align (more ADR-faithful, changes operator-visible reach). Recommend A until WP-D lands; it is Berthier's file.

## Behaviour that changes on the bench / at startup

- **Gravity model load is stricter.** `config/robot.yaml` must list every actuated joint of its URDF. Pi `/opt/marengo/config/robot.yaml` (read-only ssh check): 5 joints, URDF has the same 5, all revolute, so it loads. `config/robot_humanoid.yaml` (future scope, not loaded at runtime) would now be refused against the 5-DOF `marengo.urdf`. Slice/bench models that deliberately model fewer joints must use `from_urdf_with_held`.
- **Gravity preflight (`marengo-pi`, `motor-repl enable`) now refuses on a model error** (prints/logs the error; `motor-repl` honours `--force` as before).
- **Calibration** verdicts gain `NotConverged`; `marengo-log-cli gravity-fit` JSON/Markdown already print `fit.verdict` and σ, σ becomes `null`/`NaN` when unknown.
- Hold-at kinetic exemption is narrower at the kinematics layer; no change to the Berthier hold-at path (see K2 masking).
- Davout construction/`rebuild_limits` returns an error (not a panic, not defaults) for bad URDF limits and for a joint without a `control.joints` entry. Both were already rejected earlier by `validate_safety_config` for the second case.
